## H09: Ground-side phantom arm

- **Implementation removes the human reaction delay, not just the link.** The sketch sets `q` to "the newest sent setpoint" inside `ground_observe`. In `ground/loop.py` the operator is handed the frame from `now − tau_h`, so replacing its `q` with the newest setpoint gives the operator a zero-lag arm channel including the 250 ms human term. The "Phantom loop 250 ms" table row assumes the phantom still carries `tau_h`. H10 gets this right (setpoint logged at `now − tau_h`); H09 does not. As written, the strategy would beat baseline on `zero` by the same margin as on `leo_relay`, which is the artefact H13 warned about, and no rejection criterion checks the `zero` cell.
- **Object arithmetic is wrong by 2–4.5×.** "At ~1 cm/s drift that is millimetres" — `sim.DRIFT` is 0.020–0.045 m/s. Over the `geo_relay` loop (≈0.9 s) the box moves 18–40 mm, more than the 20 mm `GRASP_TOL`. So object dead-reckoning, not the arm phantom, is the whole `geo_relay` gain.
- **Rejection criterion (d) rejects its own success.** It says reject "if the ablation shows the gain comes from object prediction, meaning the mechanism is wrong." Given the drift arithmetic above, the gain at ≥500 ms will come from object prediction, so the hypothesis rejects itself exactly where it works. Either drop (d) or rename the claim.
- **Predicted null on the acceptance profile, confirmed.** The claim itself says <5 % on `leo_relay`; measured baseline is 3/3 at 98 % of zero throughput. Program acceptance is scored on `leo_relay` (SYNTHESIS §6). A hypothesis that concedes the acceptance profile cannot be a top-5 implementation candidate.
- **Evidence checks out but is for humans watching video.** PMC12788196: 29 participants, 150 ms, "the PD neither improved performance nor reduced workload" (verified). arXiv 1809.08627: 10 participants, "decreased time to complete task while having no effect on error rates" (verified; the −19 % figure is not in the abstract). The synthetic operator consumes state, so the testbed result is an upper bound the hypothesis admits.
- **Hook, runner and sweep do not exist.** `Strategy` has no observe seam, `run.py` has no `--strategy` flag and its `--profile` choices exclude `sweep:` (only `profiles.get` knows it). Shared with every hypothesis, but H09 lists it as "three lines" and the runner change is not counted.
- **Overlap:** same mechanism, same four sources, same seam and same failure mode as H10; stacking claim with H12 is untested; H13 (no-hypothesis) already measured this angle null on `leo_relay`.

## H10: Ground digital twin as the operator's view

- **Baseline table is stale.** The "measured today" numbers (3/3 on `geo_relay`, 7.75 s) were taken with the 50 mm envelope in `HEAD`. On the working tree (20 mm) `geo_relay` is 0/3. The predicted "+15–25 %" on `geo_relay` is now "anything above zero", which makes rejection criterion (a) trivially passable there and tells us nothing about the mechanism.
- **Twin gain at ≥500 ms is object prediction, not the arm twin.** Same drift arithmetic as H09: chase error 18–40 mm on `geo_relay` versus a 20 mm envelope. The arm half ("exact for the arm") is inside the envelope even on `geo_relay` at the operator's 7 cm/s. The ablation "object dead-reckoning off" from H09 should be a rejection criterion here, and the claim should say "object extrapolation".
- **MMT evidence is 500 ms one-way with haptics on a quasi-static task.** arXiv 2502.07922 (verified): ultrasound scan on a phantom vessel, 15 operators, 500/1000 ms one-way (1–2 s RTT), visual-haptic MMT; "none of the effort or completion time values differed significantly between 0 delay and 500 ms". A haptic-augmented quasi-static contact task is not a free-floating capture, and the twin here has no haptic channel.
- **Concedes the acceptance profile.** "It does not claim > 5 % on `leo_relay`." Measured headroom there is 2 % throughput and 0 points success. So it cannot move a primary metric where SYNTHESIS §6 scores.
- **Criterion (d) needs a metric that does not exist.** SAL/LDLJ are not in `metrics/__init__.py`; only `jerk_sum_sq` is. Either add SAL or drop it from the criterion.
- **"Peg-in-hole when it exists": it exists in `sim` now but there is no peg operator.** `SyntheticOperator.step` only knows the capture phases; `run.py` `--task` accepts only `capture`. The insertion cell is not runnable without an operator that H10 does not budget.
- **Keep-out clipping is safety theatre in this testbed.** Ground-side clipping to the cage box only matters if the operator ever commands outside it; the synthetic operator servos toward a box spawned inside reach. It adds one `mj_forward` per tick and cannot show a benefit on any cell.
- **Overlap:** H09 (duplicate), H12 (both hide the machine-loop arm lag; stacking would double-count), H13 (measured null).

## H11: Onboard terminal-grasp primitive

- **`leo_relay` criterion (a) is dead on arrival.** Requires +10 points success on `leo_relay`; measured baseline is 3/3 (and H17 found 8/10 at the 20 mm envelope through 0.5 s loop delay, with the two misses geometrically blocked). Success cannot rise 10 points from 100 %, and demos/hour has 2 % of headroom. Risk 2 in the file already says this; the file should have moved its claim to the ≥500 ms sweep and peg task instead of keeping `leo_relay` as the headline.
- **Copilot evidence is not a latency result.** arXiv 2603.17016v2 (verified): nut threading 0.49 → 0.65–0.81, IL 7/20 → 18/20 grasps, but "the paper does not explicitly specify network latency or communication link details." It shows shared autonomy helps fine alignment at whatever local latency the rig had; it does not show a primitive recovering a delayed loop. The Jin et al. 2019 "~111 ms link, 70 → 100 %" figure has no URL in H11 or in teleop_fundamentals.md and is unverifiable here.
- **SUPVIS-Justin is the precedent H11 rejects.** Verified: 832 ms RTT (800–1132), 1 Mbit/s, task-level supervised autonomy. H11 explicitly refuses goal-click supervision because the demos become robot-generated, then cites the goal-click program as its flown precedent.
- **It robot-executes the phenomenon task 2 exists to collect.** SYNTHESIS §3 task 2's unique value is "real grasp impulses on a truly free 6-DoF body". The primitive takes over exactly that segment, so the ≤10 % of frames it owns are the frames with the unique-data content. The `F_ASSIST` mask lets a trainer drop them, which means the mission collects the approach and carry that Earth simulation already provides. Risk 1 names this and mitigates it with a flag; the flag does not restore the data.
- **Ground-truth pose makes the sim result an upper bound, and the noise cell is under-specified.** "5 mm noise and 33 ms lag" is `[design choice]`; a fiducial or known-object estimator on a tumbling 16 mm box at ≤1 rad/s with a wrist camera in a 30 Hz loop has no cited accuracy figure. Without one, H11 − H11-ground (criterion d) measures the value of perfect onboard perception, not of buyable onboard perception.
- **Flight cost is the whole excluded branch.** Needs a ≥30 Hz object-pose estimator on the Jetson plus a Jetson → supervisor setpoint path, i.e. vision and a trajectory-changing primitive, both excluded by SYNTHESIS §5. Honestly declared, but the cost score must reflect it: this is the most expensive of the four to fly by an order of magnitude, and open question §9.3 (Jetson reboot rate) is unresolved.
- **Trigger is coupled to the operator's stale threshold.** The trigger is "newest setpoint commands jaw closed"; the operator closes when it sees the box within `close_at` = 0.045 m, which is now larger than `GRASP_TOL` = 0.020 m (the operator docstring says `close_at` must stay below `GRASP_TOL`). Until that constant is fixed the primitive fires at 45 mm seen distance and the 8 cm gate is moot.
- **Overlap:** H19 (the other onboard-compute branch, same Jetson → supervisor path); competes with H09/H10 for the grasp phase; H17 note on envelope tightening.

## H12: Satellite-side dead reckoning

- **Claim size versus measured headroom.** Claims ≥10 % demos/hour on `leo_relay`. Measured: `zero` 416 demos/h, `leo_relay` 410 demos/h (3 seeds). The entire link penalty is 2 %; a 60 ms lead can recover at most that. H13's earlier measurement with the 50 mm envelope gave 5 %. The rejection criterion will fire even if the extrapolator works perfectly.
- **The 0.28 %/ms slope is a human pointing result applied to a synthetic operator whose measured slope is 10× smaller.** MacKenzie & Ware's +64 % at 225 ms is for a human Fitts task. The testbed operator's time cost is ≈1.6 % per 49 ms (my run) or ≈5 % per 80 ms (H13), i.e. 0.03–0.06 %/ms; at 60 ms that is 2–4 %, not 14–20 %. The file's table has no measured anchor for the synthetic operator.
- **Chase-error arithmetic.** With drift 2–4.5 cm/s, a 60 ms lead reduces the object-chase error by 1.2–2.7 mm against a 20 mm envelope. The extrapolation is on the command stream, which the box ignores, so the failure mode that actually decides the episode (object lag) is untouched; that is why the sweep will show nothing until `geo_relay`, where the horizon bound caps the lead at 60 ms of an 885 ms loop.
- **Rakita is verified but at 250–750 ms onset latency.** "Users can quickly develop strategies to adapt to slowness delays but not onset latency delays" (verified, abstract). Their smallest added onset latency was 250 ms; nothing in the paper says 60 ms of onset latency is measurable. FoReCo (verified, ×18 sim / ×2 hardware) is a loss-recovery result, not a lead result, and H03/H04 already showed the `leo_relay` loss chain never produces a gap longer than 160 ms.
- **The ordering fix is a baseline bug, not a hypothesis.** `sat/controller.py` sorts the buffer as `sorted(buf)` on `(t_arrival, seq, sp)`, so a late old packet becomes `buf[-1]` and `Baseline.sat_step` plays it as newest (verified by reading the code; H03 and H04 flagged the same). Keying playout on `seq` is a one-line change that belongs in `baseline.py` before any hypothesis is compared. The L=0/K=8 arm isolates it, but whatever it gains is not H12's.
- **Slope clamp is not the bound the file claims.** "Slope clamped to v_max" uses `sim.VMAX` = 2 rad/s per joint; over 60 ms that permits 120 mrad, so "reversal overshoot bounded to v_max × L ≈ 4 mm" only holds for the synthetic operator's 7 cm/s Cartesian ease-off, not for the clamp.
- **Only hypothesis of the four that fits the hook as written and could run on the supervisor MCU** (`sat_step` only, seven line fits per tick, no perception). It is also the only one that alters the commanded trajectory on the satellite, which reads against SYNTHESIS §5's "no autonomy that changes the trajectory"; the file labels this honestly.
- **Overlap:** conflicts with H08 (adds buffer depth); stacks with H09/H10/H14 but double-counts the same 50 ms of arm lag with H09/H10.

## Cross-cutting notes for the synthesis agent

1. All four hypotheses were written against `GRASP_TOL` = 0.050 m and 1 cm/s drift. The working tree now has 0.020 m and 2–4.5 cm/s, and `SyntheticOperator.close_at` (0.045) violates its own documented invariant against the new `GRASP_TOL`. Every quantified table in H09–H12 must be redone once that constant is settled.
2. On the settled `leo_relay` profile the baseline is at 100 % success and 98 % throughput of `zero` (3 seeds). No latency-hiding hypothesis can clear a 10 % bar on the acceptance profile with task `capture` as built. The discriminating cells are `geo_relay`, the ≥500 ms sweep, and the peg task, which has no operator yet.
3. Shared infrastructure none of the four budgets fully: `--strategy` flag in `run.py`, `sweep:` profiles reachable from the CLI, an observe seam in `Strategy`, a peg operator, and SAL/LDLJ in `metrics`.
