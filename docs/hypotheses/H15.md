# H15: Pass-synchronous scheduler: resets off-link, two arms per operator, admit only episodes that fit the window

**Axis:** operator interface / workflow. **Author angle:** operator scheduling: align sessions with link windows and pre-stage episodes so every minute of link is a demonstration.

## Claim
Demonstration throughput is bounded by reset time, not by latency: giving each operator two arms and letting a stored onboard reset macro run on the idle arm (and in pass gaps) raises successful demos per hour by more than 10 % on every profile, and an admission rule that refuses episodes that cannot finish before loss of signal (LOS) adds a further gain per pass on `direct_gs`, with no change in success rate and zero unsafe-motion events.

## Mechanism
Earth-side collection spends most of its wall clock on resets: ALOHA gets 10–20 min of data per task from 30–60 min wall clock "because of resets and teleoperator mistakes" (data_pipeline §2.2, https://arxiv.org/html/2304.13705); the LeRobot recorder defaults to `episode_time_s=60, reset_time_s=60` (https://huggingface.co/docs/lerobot/en/il_robots). The program's metric charges reset time (data_pipeline §3). In orbit a reset is a commanded arm motion, and on `direct_gs` it burns link time inside a 9.2 min pass (SYNTHESIS §7) while the 35 min gaps burn nothing.

The baseline operator cycles episode E, reset R: rate 1/(E+R). With two arms per operator (the 8-arm scale branch, SYNTHESIS §4) the operator drives arm B while arm A plays a stored reset macro: rate 1/max(E, R+c), c the view-switch cost. Gain = (E+R)/max(E, R+c) − 1: +100 % at R = E, +50 % at R = E/2, +25 % at R = E/4. The macro is a fixed, envelope-clamped pose sequence on the supervisor (home at the velocity clamp, release with a seeded nudge, settle): the same class as retract-to-stow (SYNTHESIS §5 item 3) and as the pre-validated LOS-safe motions of Canadarm2 and Astrobee (space_teleop_prior_art §1, https://ntrs.nasa.gov/api/citations/20180003326/downloads/20180003326.pdf). It runs only between demonstrations and never alters one.

On `direct_gs` two edge effects add: both arms reset in the gap so the pass opens with an episode, and when less than E_p95 remains the scheduler starts a reset, not an episode that would straddle LOS.

## Expected effect (quantified)
Testbed capture episodes run ≈10–20 s; a home-release-settle macro at the velocity clamp should take 4–8 s `[own estimate, measured in the experiment]`, so R/E ≈ 0.3–0.5.

| Metric | Profile | Baseline (1 arm) | H15 (2 arms) | Uncertainty |
|---|---|---|---|---|
| Demos/hour | `zero`, `leo_relay` | 3600/(E+R) | +30–50 % | ±15 pts; scales with R/E |
| Demos/pass | `direct_gs` | per-pass count | +30–50 % from pipelining, +3–15 % from gap resets and admission | edge term ∝ (R + E/2)/P |
| Success rate | all | unchanged | −3 to 0 pts (view switch) | small |
| Effective latency | all | unchanged | unchanged | none |
| Unsafe-motion events | all | 0 | 0 | macro is envelope-clamped |
| Bandwidth | all | per operator | unchanged: the resetting arm streams status only, no video | none |

If in-orbit resets match Earth (R ≥ E) the gain approaches +100 %.

## How the testbed falsifies it
Add the reset macro to the sat controller and measure R_meas. Run capture, seeds 0–9, tau_h 0.25, one operator, arms ∈ {1, 2}, R ∈ {R_meas, 2·R_meas}, switch cost c ∈ {0, 2 s}, on `zero`, `leo_relay` and `direct_gs` with the pass stand-in (552 s on, gap ≥ R). REJECT if: demos/hour with 2 arms < 1.10 × 1 arm at R = R_meas, c = 2 s on `leo_relay`; success drops > 5 pts; any unsafe-motion event in a macro or at a pass edge; admission control lowers demos/pass; or R_meas < 0.1·E, leaving nothing to hide.

## Implementation sketch
This cannot live in the Strategy hook: `ground_step`/`sat_step` are per-command, and this is per-episode scheduling above that seam. Changes:
- `sat/controller.py`: after `F_DONE`, play the macro (home at the clamp, jaw open, `sim.reset` respawn), raise a new `F_READY` flag. ≈25 lines. `proto`: one flag bit.
- `run.py`: `--arms 2`, `--pass-on/--pass-off`, `--switch-s`; a scheduler with two sat threads and links that routes the one ground loop to the ready arm and applies the E_p95 rule. ≈60 lines.
- `metrics`: charge reset and switch wall time in demos/hour per data_pipeline §3. ≈5 lines.
- Pass windows are already owed to SYNTHESIS §7.

## Cost / complexity
8–12 engineering hours. Runtime ≈1.5 h realtime (3 profiles × 2 arm counts × 2 R × 2 c × 10 seeds × ≈25 s). Satellite side: one stored pose sequence and one flag on the rad-tolerant supervisor, within decision (c); no Jetson. Mission side it presumes the 8-arm scale branch, or 2 operators per 4 arms. Not the onboard-compute branch.

## Risks and failure modes
- Tasks 1 and 3 (granular, liquid) may need a vision-verified pour-back a blind macro cannot do; the gain then covers tasks 2, 4, 5 only.
- A released object may drift off the start region; the cage bounds it (SYNTHESIS §3) but the macro cannot confirm placement.
- The synthetic operator has zero view-switch cost; humans pay hundreds of ms per switch (Monsell 2003, https://doi.org/10.1016/S1364-6613(03)00028-7) and may need seconds to re-orient to a new camera. The `switch_s` knob bounds this.
- A verifier may class the macro as excluded autonomy; it is retract-to-stow plus a release step.

## Confidence
0.7 that two arms beat one by >10 % demos/hour at the testbed's measured R: the arithmetic is deterministic once R is known, and Earth data says R is comparable to E. 0.5 for the `direct_gs` edge terms alone, which are small when passes are long relative to E+R.
