NO HYPOTHESIS: Carrying a short window of setpoints per packet (previous K for loss cover, next N extrapolated for gap cover) is sound transport engineering (RFC 2198 redundant payloads, Opus in-band FEC, Source engine `cl_cmdbackup`; https://www.rfc-editor.org/rfc/rfc2198, https://www.rfc-editor.org/rfc/rfc6716#section-2.1.7, https://developer.valvesoftware.com/wiki/Source_Multiplayer_Networking) but it cannot plausibly move a primary metric by 10 % on any SYNTHESIS §7 profile against this baseline. The artefact it removes is small: in `strategies/baseline.py` one lost 50 Hz command costs a 20 ms freeze and a half-interval catch-up step, which at the operator's 7 cm/s ceiling is ≤1.4 mm of deferred path and a 0.7 mm step against a 50 mm capture envelope; `leo_relay` loss is 1.1 % long-run with Gilbert-Elliott bursts of mean 5 packets at 30 % loss, so a ≥3-packet run (60 ms freeze) occurs in ≈2.7 % of bursts and a ≥5-packet run in 0.24 %, and the literature places impairment onset at 67 ms of jitter amplitude with a "comparatively small" effect (teleop_fundamentals §1.3, Beech 2024). Holds are not touched: a 300 ms hold needs 15 consecutive losses (0.3^15 ≈ 1e-8 per burst), so every hold comes from the 1.7 h⁻¹ outages whose minimum duration (0.3 s) exceeds any defensible future horizon, and playing extrapolated points into an outage is exactly the "stale trajectory continuation" that SYNTHESIS §6 counts as unsafe motion. Using the future points as uplink latency compensation could hide at most the 30 ms uplink plus 30 ms playout of a 333 ms loop, and the evidence says predictive aids return nothing below 150 ms RTT (SYNTHESIS §10; teleop_fundamentals §4). The testbed would not even see the change where it matters for data quality: `metrics` computes jerk and `record` stores `action` from the ground-side command stream before the link, so loss glitches never enter the dataset. The one thing worth keeping is an engineering note for the transport baseline, not a hypothesis: piggybacking the previous setpoint (K=1, 96 B/packet) is a strictly cheaper form of the duplicate-send the synthesis already assumes (2 × 68 B) and should replace it when the uplink is implemented; it would matter measurably only at loss rates ≥5–10 %, which no profile in the program has and which inventing a profile to reach would be padding.
